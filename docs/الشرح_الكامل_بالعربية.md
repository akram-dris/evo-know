# الشرح الكامل للمشروع بالعربية

## أولاً: ما هو هذا المشروع؟

هذا مشروع تخرج ماستر في هندسة البرمجيات بجامعة سعد دحلب - البليدة 1، تحت إشراف الأستاذة شيخي إيمان.

**العنوان الرسمي**: استخدام تقنيات الذكاء الاصطناعي لتنفيذ نظام قابل للتشغيل البيني لإدارة المعرفة المؤسسية المبني على الحوسبة السحابية.

**الفكرة ببساطة**: بناء نظام ذكي يساعد المؤسسات على تحديث معارفها تلقائياً باستخدام الذكاء الاصطناعي، مع واجهة ويب تفاعلية متطورة مبنية بـ Vue.js 3 وTailwind CSS كنقطة تفاعل وتسيير، وبنية Cloud Native (خدمات مصغرة).

## ثانياً: من أين جاء هذا المشروع؟ (السياق الأكاديمي)

### 2.1 أطروحة الدكتوراه للمشرفة
الأستاذة شيخي إيمان اقترحت في أطروحتها إطار عمل (Framework) لإدارة المعرفة المؤسسية مبني على Cloud Computing. هذا الإطار يشمل 7 عمليات فرعية:
1. **رصد المعرفة** (Repérage) ← تم تنفيذه في مشاريع ماستر سابقة
2. **اكتساب المعرفة** (Acquisition) ← تم تنفيذه سابقاً
3. **صياغة المعرفة** (Formalisation) ← تم تنفيذه سابقاً
4. **مشاركة المعرفة** (Partage) ← نفذته إكرام في المذكرة السابقة
5. **استخدام المعرفة** (Utilisation) ← لم يُنفذ بعد
6. **تحديث المعرفة** (Mise à jour) ← **هذا هو مشروعنا نحن!**
7. **البيئة المؤسسية** (Environnement) ← لم يُنفذ بعد

### 2.2 مذكرة إكرام (العمل السابق المباشر)
إكرام بنت نظام لمشاركة المعرفة باستخدام Spring Boot + Eureka + Docker + Prometheus. أهم ما قدمته نظرياً:
- **تعريف أول** لعملية تحديث المعرفة، قسمتها إلى 4 عمليات فرعية:
  - الإثراء (Enrichissement)
  - التغيير والتنقيح (Changement & Raffinement)
  - التقييم (Évaluation)
  - التطوير (Développement)
- لكن تعريفها كان **محوره الإنسان فقط** بدون ذكاء اصطناعي

### 2.3 مساهمتنا الجديدة (ملف 1.docx)
في ملف الـ docx أضفنا:
- **جدول حالة الفن**: 25+ بحث علمي عن AI × KM (من 2015 إلى 2025)
- **جدول التقنيات**: ربط كل عملية فرعية بتقنيات IA محددة
- **العملية الفرعية الخامسة**: الأتمتة والتنسيق بالذكاء الاصطناعي (Orchestration) ← هذا ابتكارنا الجديد

## ثالثاً: المهام الخمس المختارة للتنفيذ

المشرفة قالت بوضوح في docs.txt: مستحيل تنفيذ كل شيء. اختارت 5 مهام محددة:

### المهمة 1: التنبؤ باحتياجات التحديث (T1)
- **من أي عملية فرعية؟** التقييم
- **ماذا تفعل؟** تتوقع متى ستصبح وثيقة معينة قديمة/متقادمة
- **تقنيات الذكاء الاصطناعي**: LSTM (شبكة عصبية)، Prophet (فيسبوك)، ARIMA
- **كيف تعمل؟**
  - تأخذ بيانات: عمر الوثيقة، عدد مرات الوصول، اتجاه الاستخدام
  - تُدرّب نموذج سلسلة زمنية (Time Series)
  - تُخرج "نقاط خطر التقادم" من 0.0 (جديدة) إلى 1.0 (قديمة جداً)
- **التطبيق العملي بالكود**:
  - `backend/services/t1-prediction/` ← مجلد الخدمة المصغرة
  - `models/prophet_model.py` ← نموذج Prophet
  - `models/lstm_model.py` ← نموذج LSTM بـ PyTorch
  - `scoring.py` ← حساب النقاط النهائية (مزيج مرجّح من عدة عوامل)
  - المعادلة: `النقطة = 0.3 × عامل_العمر + 0.5 × عامل_الاتجاه + 0.2 × عامل_الاستبدال`

### المهمة 2: التوليد التلقائي لتقارير التحديث (T2)
- **من أي عملية فرعية؟** التقييم
- **ماذا تفعل؟** تولّد تقارير مكتوبة بلغة طبيعية تلقائياً
- **تقنيات الذكاء الاصطناعي**: LLM (نماذج اللغة الكبيرة مثل Gemini)، NLG
- **أنواع التقارير**:
  - تقرير أسبوعي (كل جمعة تلقائياً)
  - تقرير تنبيه (عند اكتشاف وثيقة متقادمة)
  - تقرير دمج (بعد دمج معارف مكررة)
  - تقرير تناقض (بعد اكتشاف تناقضات)
  - تقرير اكتشاف (عند اكتشاف علاقات جديدة)
- **التطبيق**: نرسل البيانات المجمعة لـ Gemini API مع prompt مهيكل → يُرجع تقرير Markdown جاهز

### المهمة 3: الدمج الذكي للمعارف (T3)
- **من أي عملية فرعية؟** التغيير والتنقيح
- **ماذا تفعل؟** تكتشف المعارف المكررة وتدمجها تلقائياً
- **تقنيات الذكاء الاصطناعي**: K-Means، DBSCAN (تجميع دلالي)، إزالة التكرار بـ NLP
- **كيف تعمل؟**
  1. تأخذ كل embeddings من قاعدة FAISS
  2. تحسب التشابه الدلالي (cosine similarity)
  3. تُجمّع القطع المتشابهة بـ DBSCAN (العتبة: 0.85)
  4. لكل مجموعة فيها أكثر من عنصر → تستخدم LLM لدمجها في نص واحد شامل
  5. تُحدّث قاعدة البيانات وقاعدة المعرفة (Graph)

### المهمة 4: التحليل التلقائي للتناسق (T4)
- **من أي عملية فرعية؟** التغيير والتنقيح
- **ماذا تفعل؟** تكتشف التناقضات بين المعارف المخزنة
- **تقنيات الذكاء الاصطناعي**: NLI (Natural Language Inference)، محركات استدلال، Knowledge Graphs
- **طريقتان متكاملتان**:
  - **الطريقة 1 (NLI)**: نموذج `nli-deberta-v3-base` يأخذ زوج نصوص → يصنفها: تأكيد/حياد/تناقض
  - **الطريقة 2 (Graph)**: استعلامات Cypher على Neo4j لاكتشاف تناقضات هيكلية
- **تحسين**: لا نفحص كل الأزواج (O(n²))، بل فقط الأزواج المتشابهة دلالياً (نفس الموضوع)

### المهمة 5: الاكتشاف التلقائي للمعارف (T5)
- **من أي عملية فرعية؟** التطوير
- **ماذا تفعل؟** تكتشف علاقات مخفية بين المفاهيم
- **تقنيات الذكاء الاصطناعي**: NER، Apriori/FP-Growth، GNN
- **ثلاث تقنيات متكاملة**:
  - **NER**: استخراج الكيانات (أشخاص، تقنيات، عمليات) باستخدام CamemBERT (يدعم الفرنسية)
  - **Association Rules**: اكتشاف أنماط التلازم (Apriori) ← "الوثائق التي تذكر الموضوع A غالباً تذكر الموضوع B أيضاً"
  - **Link Prediction**: التنبؤ بروابط مفقودة في الـ Knowledge Graph

## تاسعاً: صفحات واجهة الويب بالتفصيل (Vue.js 3)

تتألف الواجهة الرسومية المبنية بالـ Vue 3 والـ Tailwind CSS من الصفحات التالية:
1. **لوحة التحكم (Dashboard)**: تعرض الحالة العامة للنظام، الرسوم البيانية للتطور التاريخي، والتنبيهات النشطة.
2. **التنبؤ بالتقادم (/prediction)**: تتيح تفعيل نماذج التنبؤ (LSTM/Prophet)، وعرض منحنيات Fraîcheur والمهام العاجلة.
3. **التقارير التلقائية (/reports)**: لعرض التقارير المصنفة مع التوثيق المرجعي وعقد مقارنة الاختلافات (Diff Viewer).
4. **الدمج الذكي (/fusion)**: تعرض تمثيل العناقيد ثنائية الأبعاد (2D Scatter Plot) عبر D3 وإجراء دمج المستندات.
5. **تحليل التناسق (/consistency)**: يعرض مخطط شبكة المعرفة (Neo4j Force Graph) والتناقضات المكتشفة مع خيارات الحل.
6. **الاكتشاف التلقائي (/discovery)**: نافذة رفع المستندات واستعراض الكيانات المستخرجة (NER) وتوقعات روابط الرسوم البيانية.
7. **مستودع المعارف (/knowledge-base)**: الواجهة الكلاسيكية لإدارة المستندات والبحث الدلالي الفيكتوري.
8. **المراقبة والدعم (/monitoring)**: لمتابعة حالة الحاويات (Consul) وأداء النماذج ومسار التنفيذ (Traces).
9. **سجل التدقيق والـ XAI (/audit)**: دفتر العمليات لإثبات شفافية الذكاء الاصطناعي مع إمكانية التراجع البشري (Override).
10. **الإعدادات (/settings)**: تسيير الحسابات، صلاحيات الأدوار، والمفاتيح البرمجية ومفاتيح الويب (Webhooks).

## عاشراً: العملية الفرعية الخامسة (الابتكار الرئيسي)

هذا هو **الإسهام الأصلي** لهذا المشروع. الـ Orchestrator يعمل كعقل مركزي:

1. **الجدولة**: فحص يومي الساعة 2 صباحاً (T1→T5→T3→T4→T2)
2. **المراقبة المستمرة**: كل 30 دقيقة يفحص إن كانت هناك وثائق خطيرة
3. **حل النزاعات تلقائياً**:
   - إذا أحد النصين أحدث بـ 6+ أشهر → يُفضَّل الأحدث
   - إذا الثقة منخفضة → يُصعَّد للإنسان عبر لوحة التنبيهات في الـ Dashboard
   - إذا معقد → يُستخدم LLM للتحكيم
4. **التتبع (XAI)**: كل قرار يُسجَّل في audit_log مع شرح بلغة طبيعية

## الحادي عشر: التشغيل البيني (Interoperability)

هذا أحد الهدفين الرئيسيين من اقتراح الأطروحة. المشرفة قالت إن النموذج السابق يفتقر لهذا الجانب:

- **REST API محمي بـ JWT**: يسمح لأنظمة المؤسسة الأخرى (HR, ERP) بالتفاعل مع نظام المعرفة
- **Webhooks**: النظام يُرسل إشعارات push لأنظمة خارجية (مثل Slack أو MS Teams) عند حدوث تحديثات
- **Swagger UI**: توثيق تلقائي لكل الـ API endpoints
- **واجهة الويب الموحدة**: تمثل لوحة التحكم والتسيير المركزية للنظام لجميع الفئات المستهدفة
